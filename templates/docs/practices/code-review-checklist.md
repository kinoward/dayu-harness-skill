# 代码 Review 自检清单

> 触发时机：审查 PR 变更、完成一段实现后自查。注意：这不是完整清单，是高频问题模式的快速核对表。

## 通用模式

1. **资源释放**：文件句柄、数据库连接、网络 socket 是否在异常路径中也正确关闭
2. **输入校验**：API 路径参数、postMessage origin、用户输入是否校验了类型和边界值
3. **错误处理**：异常捕获是否过宽（`except Exception` / bare `try/catch`），是否吞掉了编程错误；应显式列出预期异常类型
4. **并发安全**：共享状态的读写是否有竞态条件；缓存的单例/Promise 在 reject 时是否清空了失败状态
5. **边界条件**：空列表、null/undefined、超长输入、负数金额等边界是否处理
6. **日志敏感信息**：错误日志中是否泄漏了 token、密码、个人信息

## 技术栈特定参考

> 以下为 Node.js/TypeScript 项目中的常见模式，其他技术栈可参考对应模式或删除本节。

1. **外部数据缺少运行时类型检查**：`as` 断言、`json.loads()` 解析后不做类型守卫 → 对应通用 #2
2. **工具函数分散在组件中**：格式化、转换等通用逻辑放公共模块，不在每个组件内复制
3. **数组索引 vs 业务 ID 混淆**：排序后数组位置不等于元素的 `index` 属性，跨模块传递必须显式映射 → 对应通用 #4
