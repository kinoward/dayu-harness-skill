# 开发与测试纪律

> 触发时机：开始、结束或排查环境问题时读取。违反这些纪律的典型后果：端口占用、内存压力、磁盘冗余下载。

## 1. 结束开发/测试时关闭所有相关进程

每次开发或测试会话结束时，主动关闭所有为此次工作启动的后台进程和程序。

### 适用范围

- dev server（如 `npm run dev`、`vite`、`uvicorn`）
- watch 进程（如 `vitest --watch`、`pytest -W`）
- 浏览器实例（Playwright `launchPersistentContext`）
- 长跑脚本

### 为什么必须主动关闭

- **端口占用**：下次启动同一 server 会 `Address already in use`
- **内存压力**：孤儿进程累积占用虚拟内存，触发 swap thrashing
- **AI 协作时**：Claude 在每段完整开发/测试工作收尾后应主动巡检并清理

### 操作规范

- **巡检命令**（收尾或怀疑资源问题时跑一次）：
  ```bash
  ps aux | grep -iE 'node|vite|vitest|playwright|python|uvicorn' | grep -v grep
  ```
- **kill 策略**：默认 `kill <pid>`（SIGTERM）；不响应则 `kill -9 <pid>`
- **AI 协作时**：每段开发/测试收尾后主动巡检清理，不假设进程会自己退出

## 2. 保留项目特定资产，不主动删除

开发或测试涉及的**大文件资产**保留作为本地缓存供后续复用，不主动删除，也不提交到远程仓库。

### 适用范围

<!-- 每个项目在此定义需要保留的资产，例如： -->
<!-- - 大型依赖缓存（node_modules、.venv、~/.cache 等） -->
<!-- - Docker 镜像 -->
<!-- - 大型数据集或二进制资产 -->

### 为什么保留

- 大型资产每次重新下载浪费带宽和时间
- 开发/测试需要反复验证行为，频繁重下是纯开销

### 操作规范（红线）

- 不要调用删除 API
- 不要 `rm -rf` 缓存目录
- 测试用临时路径（pytest `tmp_path`、vitest mock），不触及全局缓存
- `.gitignore` 覆盖大文件资产，防止意外 commit

### 用户手动清理

如果磁盘需要回收，由用户从命令行操作。不要让代码路径或自动化脚本触达缓存目录。

## 3. 大文件/长链路操作分层验证

验证涉及大文件（>100MB）下载或长链路操作时，按两层走，不要一开始就发起完整操作阻塞等。

### 两层结构

| 层 | 目的 | 方式 | 预期耗时 |
|----|------|------|---------|
| **smoke** | 验证连通性、授权、路径写入权限 | 最小化过滤，只拉元数据 | 几秒 |
| **full** | 验证完整吞吐、中途失败、断点续传 | 完整操作，后台执行 | 数十秒到几分钟 |

### 操作流程

1. **第一层 smoke（阻塞）**：跑通 = 授权 OK / 路径可写。问题立刻暴露
2. **第二层 full（后台）**：smoke 过了再发起完整操作，前台并行做其他任务
3. 两层耗时落入 Test Plan 作为证据

### 反模式

- 跳过 smoke 直接跑完整操作——若挂起要等很久才知道
- 前台阻塞等完整操作——无谓串行化
